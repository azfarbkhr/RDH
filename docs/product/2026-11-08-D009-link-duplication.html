D-009: Link duplication contents

Decision: Product Owner decision recorded 8 November 2026. Related ticket: T-0002 — Add link names, tags, generated slugs, and archiving. Independent review: T-0002 readiness review.

Question

When a user duplicates a short link, should the copy preserve only its destination and name, or also its tags and routing rules?

Evidence

  • T-0002's current behavior already supports country/device routing rules and owner-scoped link records.
  • Tags and duplication are planned together as link-library organization tools.
  • The project goal is to make conditional destinations easy to manage. Copying routing configuration preserves the behavior that makes the source link useful.
  • Click events are tied to the source link and represent historical traffic. Copying them would misstate analytics for the new link.
  • The independent reviewer found this was the only open T-0002 product decision; migration, ownership, archive, and slug-collision criteria were otherwise feasible.

Decision

For T-0002, duplicate the link name, destination, tags, and routing rules into a new active link with its own globally unique slug and new routing-rule IDs. Do not duplicate click events, analytics, the old slug, or archive state.

Rationale and trade-offs

Copying tags and routing rules preserves the source's editable organization and conditional behavior, reducing repeated setup for a closely related link. The copy begins receiving its own traffic and analytics. A new active link can still receive traffic immediately, so the UI should make the copied destination and rules reviewable before sharing. Copying only name and destination would be simpler but would discard the routing behavior central to this product.

Scope and conditions

This is a delegated Product Owner decision within the owner's requested link-duplication feature; no additional human-owner authorization is required. It does not authorize copying analytics, moving links between owners/workspaces, or implementing workspace memberships. T-0025's later read-only invitation boundary remains separate.
