Review finding

  1. AC05 does not define the full preservation boundary it promises. The outcome and scope promise preservation of existing Redirect Hub SQLite records and associated data. The ticket's own current-evidence section identifies transactional workspace-membership backfill, but AC05 checks identifiers only for users, links, rules, click events, and API tokens. The current schema also contains workspaces, workspace memberships, invitations, tags, link-tag relationships, and sessions. It is unclear which of these must survive schema upgrades and which (especially active sessions and bearer invitations) should be invalidated. “A previously supported schema” also does not identify the historical schema fixture(s) to test. This leaves the highest-risk data-preservation requirement open to inconsistent implementation and review.

Bounded correction: In AC05, enumerate the supported database fixture baseline(s) and the durable entities/relationships whose IDs, ownership, slugs, and redirect behavior must be preserved. State explicitly whether sessions and outstanding invitations are preserved or invalidated on upgrade. Include workspace membership, tags, and link-tag associations where they exist. Keep synthetic temporary database verification and the prohibition on accessing the normal database path.
