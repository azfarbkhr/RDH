Technical

The current application has a Vite-served React interface, a TypeScript API built with Hono and @hono/node-server, and a local SQLite database accessed through Node's node:sqlite module.

Run the development workspace

From the repository root, use Node.js 22 or later and pnpm:

pnpm install
pnpm dev

Open http://127.0.0.1:5173. Vite serves the interface and proxies /api and /l requests to Hono on 127.0.0.1:8787.

The API creates data/redirect-hub.sqlite at the repository root on startup. Set DATABASE_PATH to change its location or PORT to change the API port. Behind a reverse proxy, set PUBLIC_BASE_URL to the public HTTP(S) origin (without a path) and route /api and /l to Hono. Short URLs then use that canonical host, and direct self-redirect checks use the same origin.

Local MCP server

A local stdio server is available with pnpm mcp. For an MCP host, launch Node directly from apps/api/ with --import tsx src/mcp.ts so package-manager messages do not enter the protocol stream. Set REDIRECT_HUB_API_URL and REDIRECT_HUB_API_TOKEN in the host configuration. Read tools are registered by default. To register write tools, set REDIRECT_HUB_MCP_ALLOW_WRITES=1 and supply a read/write token. See the local MCP setup guide.

The MCP process defaults to the Hono API on loopback and inherits its owner checks and API-token scopes. A non-loopback API URL must use HTTPS. The MCP transport itself is local stdio; remote MCP transport has not been added.

Current API

  • GET /api/health returns a service health response.
  • GET /api/auth/session, POST /api/auth/register, POST /api/auth/login, and POST /api/auth/logout report or change the owner session. Registration creates an independent owner account and starts its session; only the first account adopts legacy links with no owner. Later accounts do not claim those links.
  • GET /api/auth/tokens, POST /api/auth/tokens, and DELETE /api/auth/tokens/:id manage an owner's hashed read or read/write bearer tokens. A token value is returned only once at creation.
  • GET /api/links lists links owned by the signed-in account.
  • POST /api/links creates a link owned by the signed-in account with a name, HTTP(S) destination, optional custom slug, and optional UTM source, medium, campaign, term, and content values.
  • PATCH /api/links/:id updates the signed-in owner's link name, HTTP(S) destination, or optional UTM source/medium/campaign/term/content values while preserving the short URL. UTM values are trimmed, limited to 200 Unicode code points, and cleared with null, empty, or whitespace-only values; omitted PATCH values are unchanged.
  • GET /api/links/:id/rules lists ordered routing rules; POST on the same path adds a country and/or device rule, up to 20 per link.
  • DELETE /api/links/:id/rules/:ruleId removes an owner-scoped rule; PATCH /api/links/:id/rules/:ruleId/priority moves a rule up or down.
  • POST /api/links/:id/simulate previews a visitor's selected destination after applying that link's saved UTM values, without recording a click.
  • GET /api/analytics returns bot-filtered click totals, last-seven-day totals, device groups, top links, and available country and matched-rule aggregates.
  • GET /l/:slug resolves the first matching rule, then applies saved link-level UTM values and returns a temporary redirect. With no match, the link's saved destination is used. Visitor query parameters are not forwarded. Existing destination UTM keys are replaced, repeated non-UTM query pairs and the fragment are preserved.

Build with pnpm build. The frontend and API build separately inside apps/web/ and apps/api/.

Prototype boundary

Self-service registration can create multiple independent owner accounts on an instance. Each account sees only its own links, rules, tags, tokens, and analytics; registration does not provide workspace sharing or invitations. Sessions are opaque random tokens whose hashes are stored in SQLite; the browser cookie is HTTP-only and SameSite Lax. Passwords use Node.js scrypt. There is no account invitation or password recovery yet. Registration has no rate limit. The API binds to loopback. This remains a local/self-hosted prototype and is not prepared for public deployment; do not expose it to a network before deployment security and operational setup are complete.

Country is only derived from CF-IPCountry when COUNTRY_HEADER_PROVIDER=cloudflare; enable this only behind a trusted proxy configured to replace the header. Device classification is coarse. Referrer hostname is recorded but is not currently returned as an analytics breakdown. Token expiry, automatic rotation, retention controls, remote MCP transport, date filters, and CSV export have not been implemented.

The repository also contains the earlier Django prototype in redirect_hub/. The new Node/React workspace lives in apps/; migration or removal of the Django source has not been done.
