Workspaces and invitations

Redirect Hub resolves each authenticated request to a workspace membership. Existing accounts receive a private owner workspace during database startup migration; existing links are associated with the matching account workspace without changing public slugs or click history.

Workspace model

  • workspaces records the workspace and its owner.
  • workspace_memberships connects users with an owner or member role.
  • links.workspace_id scopes link, rule, tag, and analytics reads. Legacy links with no owner remain unassigned until the existing first-account adoption behavior applies.

The browser sends the selected workspace in X-Workspace-ID. The API verifies membership for every request. API tokens use the owner's private workspace and cannot select a joined workspace.

Invitation lifecycle

Only an authenticated owner session can create, list, and revoke an invitation. Creation generates a cryptographically random bearer secret, stores its SHA-256 hash, and returns the copyable URL once. The secret is placed in a URL fragment so it is not sent in the HTTP request URL. The client removes that fragment from browser history before submitting the secret in a POST JSON body.

Invitations expire seven days after creation and may be redeemed only once. Redemption creates a new user, personal workspace, read-only membership, consumed invitation state, and session atomically. A duplicate email or invalid, expired, revoked, or used invitation returns a generic failure. No email verification or email delivery occurs.

Authorization limits

Members may read joined-workspace links, routing rules, tags, and analytics and use the side-effect-free routing simulator. Mutations, invitation management, and API-token management require an owner role. Member sessions cannot use bearer API tokens or MCP to access the shared workspace; an invitee's personal workspace remains separate.

This is a local/self-hosted prototype. Use HTTPS and a trusted proxy for network exposure, protect invitation URLs as credentials, and review deployment security before exposing an instance.
