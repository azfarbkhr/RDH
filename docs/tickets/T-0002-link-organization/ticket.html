Add link names, tags, generated slugs, and archiving

Ticket: T-0002. Delivery role: developer. Relative effort: M. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Complete the link-library organization workflow with owner-scoped tags, tag/archive filtering, explicit archive/unarchive, and duplication. Keep the already working human-readable names, optional custom/generated slugs, name/slug/destination search, editing, copying, and redirect behavior intact.

Current evidence

Verified in apps/api/src/db.ts: links stores globally unique slug, name, destination, timestamps, and nullable owner_id; redirect rules and click events reference link IDs. Startup performs inline additive SQLite migrations. apps/api/src/index.ts scopes list and update queries by authenticated owner, creates names with a supplied slug or 5-byte random base64url slug, returns 409 for a duplicate slug, and resolves public redirects by slug regardless of owner. apps/web/src/main.tsx already supports names, custom/generated slugs, edit, details, and client-side search across name/slug/destination. Tags, archive state, tag/archive filters, and duplication are absent. The one-account registration constraint means two-owner isolation needs synthetic owner/session fixtures, not normal registration.

Feature inspiration: Dub create-link reference, inspected 8 November 2026. The scope and effort are Redirect Hub recommendations, not claims about Dub implementation cost. See research and source limits and owner direction and planning assumptions.

Scope and exclusions

Include tags, tag filters, active/archive views, archive/unarchive, and duplicate action for existing links. Keep search over name, slug, and destination. Duplicate the link name, destination, tags, and routing rules with a new globally unique slug; do not copy click events or analytics. An archived link remains publicly redirectable and can be unarchived. No nested folders, multi-user workspace migration, roles/permissions, bulk import/export, tag sharing, or custom domains. User/workspace ownership remains the current owner_id model; T-0025 separately handles any later move to shared workspace membership.

Acceptance checks

Every pre-existing link defaults to active/unarchived, and its short URL still redirects to the same destination.
AC02Owners can create, assign, remove, and filter by tags. Tag names are trimmed, 1–40 characters, and case-insensitively unique within one owner; a tag or link belonging to another owner is not visible or mutable. A user can filter by one selected tag.
AC03Link search returns only the current owner's matches for name, slug, or destination, and combines with the active/archive view and selected tag filter without exposing other-owner rows.
AC04Archive/unarchive actions persist and update the list immediately. Active view excludes archived links; archived view includes them. Archiving changes no short URL or redirect rule, and archived links continue returning the configured 302 destination.
AC05Duplicate creates a new link owned by the same owner with the same name, destination, tags, and routing rules; it has a new globally unique slug, active status, and no copied click events. The new URL redirects to the copied destination/routing result.
AC06Explicit custom-slug collisions return a clear 409 validation response without changing either link. Generated-slug collisions retry a bounded number of times, then return a clear error; no duplicate slug is persisted under concurrent creation.

Research, design, and interfaces

Extend SQLite initialization/migration, owner-scoped API contracts, and the React Links workflow. Use a tag/link relation or an equivalent normalized structure that enforces owner consistency. Keep tag queries, archive filters, and duplication operations scoped to authenticated owner. Public redirect lookup must ignore archive state. Duplicate routing rules by value with new rule IDs/priorities; analytics remain associated only with the source link. Preserve the current reserved URL scheme, slug constraints (3–48 ASCII letters/numbers/hyphen/underscore), and global slug uniqueness. This is a cross-layer feature for API, UI, SQLite migration, and later shared service consumers; do not implement T-0025 workspace membership here.
