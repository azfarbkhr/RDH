Expose an authenticated link-management API

Ticket: T-0011. Delivery role: developer. Relative effort: M. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Expose versioned JSON endpoints for listing, reading, creating, editing, archiving, rule management, side-effect-free simulation, and aggregate analytics. Reuse the same owner-scoped service operations as the UI.

Current evidence

The Hono API now accepts opaque bearer tokens whose SHA-256 hashes are stored in SQLite. The signed-in owner can create read-only or read/write tokens, list active tokens, and revoke them. Secrets are returned only on creation and capped at 10 active tokens per owner. Middleware enforces read scope for GET and simulation, and write scope for mutations; account sessions retain both scopes. The MCP tools use these endpoints. Pagination, rate limits, idempotency, explicit configuration versions, and API reference documentation remain open.

Feature inspiration: Dub Links, inspected 8 November 2026. The scope and effort are Redirect Hub recommendations, not claims about Dub implementation cost. See research and source limits and owner direction and planning assumptions.

Scope and exclusions

No public anonymous creation, destructive deletion endpoint, or SDK family.
