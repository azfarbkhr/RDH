Record redirect events with routing context and retention

Ticket: T-0009. Delivery role: developer. Relative effort: M. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Persist minimal redirect events: timestamp, link ID, matched rule/default, destination snapshot, coarse country, device, referrer hostname, and known-bot classification. Treat unavailable context as unknown.

Current evidence

The Hono redirect handler records a UUID, timestamp, link ID, matched rule ID, optional country code, coarse device class, referrer hostname, and bot flag. It does not store raw IPs or full user-agent strings. Simulation uses a separate endpoint and does not write click events. Destination snapshots, retention/cleanup, HEAD handling, and failure isolation for analytics writes remain open.

Feature inspiration: Dub Links, inspected 8 November 2026. The scope and effort are Redirect Hub recommendations, not claims about Dub implementation cost. See research and source limits and owner direction and planning assumptions.

Scope and exclusions

No fingerprinting, conversion tracking, raw-IP visitor log, or mandatory queue infrastructure.
