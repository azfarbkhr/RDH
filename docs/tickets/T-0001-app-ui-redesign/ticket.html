Redesign the application UI and core workflows

Ticket: T-0001. Delivery role: ui-developer (ticket-specific scope below). Relative effort: M. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Make the existing Redirect Hub React application clear and comfortable to use across first-run account setup, link management, routing, analytics, and API token settings. Establish a reusable visual system and a responsive, keyboard-operable application with distinct pages for distinct tasks. The application must not put analytics, link creation, and the full link collection together on one workspace page. The GitHub README is the public showcase; the application opens directly, with no marketing landing page.

Current evidence

The React workspace under apps/web/ currently includes first-owner setup and sign-in, named link creation/listing/editing/copying, click summary and available country/rule breakdowns, a routing-rule editor and visitor simulator, and an API token panel. The shared stylesheet uses neutral surfaces, typography, borders, and a green accent. These features are present in code, but no browser screenshots, responsive walkthrough, keyboard review, or contrast measurements have been recorded. Do not treat their presence as evidence that their visual or accessibility acceptance checks pass.

Direction comes from owner decision D-002 and the UI acceptance rubric in product decisions. Feature research is linked from the Dub analysis; this ticket covers presentation and workflow clarity, not the underlying routing, analytics, or token capabilities.

Scope and exclusions

Rework the screens and flows already implemented in apps/web/: owner setup/sign-in; a focused overview; a dedicated links collection; a focused create-link flow; individual link details with Overview, Routing, Analytics, and Settings areas; a dedicated analytics page; and a developer/API access page. Use persistent, compact navigation to move between those pages. Do not display the analytics dashboard, create form, and entire link collection together as one page. Keep each page centered on one primary task, with routing rules and the visitor simulator kept in the link's Routing area. Improve responsive behavior, hierarchy, feedback, and keyboard interaction without changing the underlying API contracts. Keep human-friendly link names prominent.

Do not add a marketing site or implement new product capabilities owned by other tickets. Do not invent traffic, conversion, or user metrics. Preserve the owner-approved quiet neutral surfaces, readable typography, generous spacing, subtle borders, and one accent. Dependencies: none.
