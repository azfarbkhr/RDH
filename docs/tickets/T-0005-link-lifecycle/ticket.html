Add link disabling, expiration, and expired destinations

Ticket: T-0005. Delivery role: developer. Relative effort: S. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Let link owners disable and re-enable redirects with an explicit active/paused control. Add timezone-aware expiration, an optional expired destination, and clear disabled/expired responses. Distinguish archive from disable. Lifecycle checks run before routing.

Current evidence

Verified in apps/api/src/db.ts and apps/api/src/index.ts: links have an owner, target, slug, and timestamps; redirect resolution currently returns a 302 and has no active/paused or expiry fields. This proposal adds lifecycle behavior not currently implemented.

Feature inspiration: Dub link expiration, inspected 8 November 2026. The scope and effort are Redirect Hub recommendations, not claims about Dub implementation cost. See research and source limits and owner direction and planning assumptions.

Scope and exclusions

Grooming baseline verified 9 November 2026: extend the existing owner-scoped POST /api/links and PATCH /api/links/:id contracts, list serialization, and React create/edit workflows. Add lifecycle gates before the existing routing resolver and UTM composition. Preserve archive as organization only, preserve tags and routing rules on disable/re-enable, and migrate existing SQLite links to enabled with no expiration or expired destination. No natural-language date parser or automatic destination health checker.

Acceptance checks

AC03Validate fallback URLs and prevent direct self-loops. Persist UTC and show timezone labels in the UI.
