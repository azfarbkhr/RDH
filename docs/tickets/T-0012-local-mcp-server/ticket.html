Expose a local MCP server for links, routing, and analytics

Ticket: T-0012. Delivery role: developer. Relative effort: M. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Provide an official TypeScript SDK stdio MCP adapter over the authenticated Hono API. Tools: list_links, get_link, list_routing_rules, create_link, update_link, create_routing_rule, delete_routing_rule, simulate_redirect, and get_analytics. Read-only tools are registered by default; write tools require both a read/write API token and an explicit local process setting.

Current evidence

A Node stdio server is implemented in apps/api/src/mcp.ts with the official @modelcontextprotocol/server package and serveStdio. It calls the authenticated Hono API using a bearer token, registers five read tools by default, and registers four write tools only when REDIRECT_HUB_MCP_ALLOW_WRITES=1 is set. API tokens are created, listed, and revoked through the owner session in the React UI. The shared Hono API enforces per-token scopes and ownership. Client handshake, tool calls, revoked/read-only token denial, and complete create-configure-simulate-analytics flow have not been runtime-verified.

Feature inspiration: Dub MCP documentation, inspected 8 November 2026. The scope and effort are Redirect Hub recommendations, not claims about Dub implementation cost. See research and source limits and owner direction and planning assumptions.

Scope and exclusions

Local stdio is the first deliverable. Browser/hosted clients need T-0018; no arbitrary URL-fetch, shell, link deletion, or password-setting tool. Rule deletion is exposed only through an explicitly enabled write tool and is marked destructive.
