Add a UTM campaign builder with destination preview

Ticket: T-0003. Delivery role: developer. Relative effort: M. S = localized addition, M = cross-layer work, L = infrastructure or complex runtime work. These are planning estimates, not commitments.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Let a link owner configure the five standard UTM values for a link, see the resulting destination URL while creating or editing it, and apply that one link-level configuration after the redirect resolver selects either its default or a country/device destination.

Current evidence

Verified current implementation: The active app is React (apps/web/src/main.tsx), Hono (apps/api/src/index.ts), and SQLite (apps/api/src/db.ts). The links table stores destination_url, owner, name, slug, and timestamps; conditional destinations live in redirect_rules. Create and update schemas currently accept link name and HTTP(S) destination (create also accepts a slug); the link serializer exposes the destination but no UTM values. The shared resolveDestination function chooses the first matching rule or the default destination. The actual redirect uses its selected URL, and the owner-scoped simulation returns its selected URL without recording a click. Neither path currently adds UTM values. Incoming request query parameters are not currently appended to the selected destination.

Proposal/inference: A single optional UTM configuration on each link is the simplest fit for the requested builder and the existing link model. Apply it after destination selection so all configured/default/rule destinations receive the same campaign values. T-0007 already describes the order as lifecycle/password gates, route selection, then UTM composition; T-0005 owns the lifecycle behavior. T-0003 should provide the persisted per-link fields and URL composition contract that T-0007 can call, without adding per-rule UTM overrides.

Feature inspiration: Dub UTM builder, inspected 8 November 2026. The scope and effort are Redirect Hub recommendations, not claims about Dub implementation cost. See research and source limits and owner direction and planning assumptions.

Scope and exclusions

  • Persist optional utm_source, utm_medium, utm_campaign, utm_term, and utm_content values on the owning link. Support set/edit/clear through create/update UI and authenticated API; return them from the link API response. Existing links with no configured values continue redirecting to their selected destination with no UTM changes.
  • Use the same URL-composition behavior for the preview, simulation result, and live redirect after the resolver selects a destination.
  • Trim leading/trailing whitespace. Treat omitted create values as unset. On update, omitted properties mean “leave unchanged”; explicit null, empty, or whitespace-only values clear that field. Reject non-string values and values longer than 200 Unicode code points with a field-specific validation error; do not silently truncate. Spaces and Unicode within accepted values are valid and must be URL-encoded by the URL implementation.
  • For each of the five standard keys, remove every existing occurrence from the selected destination, comparing the query key case-insensitively, then append exactly one canonical lower-case key if its configured value is nonempty. Thus a cleared field also removes a destination-provided value for that standard key. Preserve every non-standard query pair, including repeated keys and their order, and preserve the destination fragment.
  • Ignore the short-link request's query string for redirect composition. Do not forward visitor-supplied parameters or allow them to change the chosen destination or any configured UTM value.

Exclude conversion/revenue attribution, per-route UTM overrides, arbitrary query forwarding, and MCP-specific UI or tools. The authenticated API contract is the integration surface for later API/MCP work.

Research, design, and interfaces

Keep the builder inside the focused create-link flow and the link Settings editor, with an exact preview near the fields. Use the five canonical names as human-readable labels. Inspect API token/session ownership middleware and link serialization before implementation. Extend the link create/update API contract without changing unrelated link fields. Centralize URL composition in one function callable by UI preview, simulation, and redirect so the output cannot drift. The helper accepts a selected HTTP(S) destination and the link's optional UTM configuration; routing rules do not own separate UTM values. T-0007 must call the same helper after destination selection, while lifecycle gates remain in T-0005/T-0007 scope.
