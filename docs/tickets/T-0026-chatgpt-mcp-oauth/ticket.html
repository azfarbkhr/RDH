Connect ChatGPT to the remote MCP server with OAuth

Ticket: T-0026. Delivery role: developer. Relative effort: L.

Lifecycle, priority, dependencies, and ticket path are maintained only in the queue, sourced from tickets.jsonl.

Outcome

Provide an OAuth-protected remote MCP endpoint and a documented server URL that a supported ChatGPT connector can authorize and use.

Current evidence

T-0018 covers Streamable HTTP transport, while apps/api/src/mcp.ts currently implements local stdio MCP and API-token access. No remote MCP endpoint or OAuth authorization server exists. The owner requests an OAuth-based endpoint URL compatible with ChatGPT. Current authoritative references: OpenAI custom MCP server connection guide and MCP authorization specification.

OpenAI currently documents remote MCP connections over a public HTTPS endpoint or supported Secure MCP Tunnel. The currently documented OAuth flow requires an authorization provider that can issue refresh tokens; OpenAI advises exposing offline_access or an equivalent refresh scope when supported. The MCP HTTP server is the OAuth resource server; token issuance and consent are provided by an authorization server. These requirements and plan availability must be rechecked at delivery.

Scope and exclusions

Provide the remote MCP URL over HTTPS, MCP protected-resource discovery and OAuth challenge, token validation with correct issuer/audience/scope, per-user authorization to Redirect Hub tools, revocation/expiry behavior, and a tested supported ChatGPT connection. OAuth must keep working across token refresh. No hosted Redirect Hub service, domain purchase, automatic connector creation, broad role matrix, or claim that all ChatGPT plans support write-enabled MCP. Self-host operator configures an authorization-server integration unless the Product Owner approves building an authorization server.

Research, design, and interfaces

Use the current official MCP authorization guidance and Streamable HTTP transport specification. OpenAI's current ChatGPT connection instructions describe custom remote server setup, OAuth, and refresh-token continuity. The MCP server should validate tokens issued specifically for its canonical resource and bind tool access to the authenticated owner. The default design is to configure an external OAuth provider; building a self-contained authorization server is a separate infrastructure/security decision.
