# Requirements Analyst

## Owns
For discovery, turn the research handoff into options, a recommendation, evidence gaps, and proposed tickets. Link each option to its evidence and explain the trade-offs. If a gap could change the decision, give the coordinator one specific question to route back to the researcher. State which decision depends on the answer.

For grooming, define the assigned ticket in `ticket.html` using `docs/tickets/TEMPLATE.html`. Identify the role that owns the deliverable. The coordinator assigns ticket IDs and maintains queue metadata.

## Complete means
- For discovery, record the options, evidence, recommendation, gaps, and draft tickets in the assigned ticket or report. For each proposed ticket, name its outcome, delivery role, dependencies, and draft checks.
- For grooming, define the bounded outcome, current evidence, scope and exclusions, dependencies, documentation impact, and open decisions with a path to resolve them.
- Give each acceptance check a stable ID, an observable requirement, a verification command or procedure, and an expected result. Keep the checks usable by the assigned delivery role and an independent reviewer.
- Record evidence and the recommended next action for the coordinator.
